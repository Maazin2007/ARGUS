## Limits

- This is a software test of the status rules on simulated scenarios. It is not clinical validation.
- All three methods run the same `getStatus` function the dashboard uses.
- Sleep and mood have no spaceflight adjustment and no personal baseline in our rules, so all three methods give the same result for them.
- Every scenario value is a demo parameter chosen by the team.

## Scenarios

### Slow-onset fever

Slow-onset fever late in a Mars transit. Every value is a demo parameter chosen by the team, not a medical reference. This file and the expectations below were committed before the evaluation was first run. If any value is changed after seeing results, say so on the project page.

What we expected before running it:

- Earth range only: amber on most days of the healthy period, because the in-flight base of 37.4 °C sits above the Earth upper limit. These are false alerts.
- Adjusted range: no false alerts in the healthy period. First amber about five days after onset, once the reading passes the adjusted upper limit.
- Adjusted range and baseline: no false alerts in the healthy period. First amber earlier than the adjusted range alone, after three readings in a row leave the personal baseline.
- All three methods: red on the same day, because the critical limit is fixed and nothing moves it.

### Single odd reading

One odd body-temperature reading (a sensor glitch or typo that still passes the input check) on one day of an ordinary Mars transit stretch. Nothing is wrong with the crewmember, so every alert is a false alert. Every value is a demo parameter chosen by the team, not a medical reference. The expectations below were written before the first run, but committed together with the results (unlike fever.json, which was committed first). If any value is changed after seeing results, say so on the project page.

What we expected before running it:

- Earth range only: amber on most days, because the in-flight base of 37.4 °C sits above the Earth upper limit. All of these are false alerts.
- Adjusted range: no false alerts. The odd reading (about 37.9 °C) is still inside the adjusted range.
- Adjusted range and baseline: no false alerts. The odd reading is outside the personal baseline, but it is one reading, not three in a row.
- No method turns red, because the odd reading stays below the critical limit.

### Sudden spike

Body temperature jumps from the usual level to above the critical limit in one day and stays there, late in a Mars transit. Every value is a demo parameter chosen by the team, not a medical reference. The expectations below were written before the first run, but committed together with the results (unlike fever.json, which was committed first). If any value is changed after seeing results, say so on the project page.

What we expected before running it:

- All three methods: red on the onset day (day 0), because the reading is above the fixed critical limit.
- No method misses a spike reading.
- Earth range only: false amber in the healthy period, as in the fever test. The other two: none.

### Creeping sleep debt

Overnight sleep shrinks a little each night until it falls below the 7-hour reference, late in a Mars transit. Every value is a demo parameter chosen by the team, not a medical reference. The expectations below were written before the first run, but committed together with the results (unlike fever.json, which was committed first). If any value is changed after seeing results, say so on the project page.

What we expected before running it:

- All three methods give the same result: sleep has no spaceflight adjustment and no personal baseline in our rules, so the extra information changes nothing.
- First amber about four days after onset, once sleep drops below 7 hours.
- No red: the status engine has no critical limit for sleep (the short-sleep escalation lives on the card).
- No false alerts in the healthy period.
