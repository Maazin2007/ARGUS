# Alert test: slow-onset fever

Generated by `npm run evaluate` from `scripts/scenarios/fever.json`. Do not edit by hand.

Simulated marsTransit mission, days 173 to 212: 30 healthy days at 37.4 ± 0.1 °C, then a rise of 0.15 °C per day for 10 days from mission day 203.

## Results

| Method | First amber (days after onset) | First red (days after onset) | Missed (fever readings left green) | False amber (healthy period) | False red (healthy period) |
|---|---|---|---|---|---|
| Earth range only | 0 | 7 | 0 | 30 | 0 |
| Adjusted range | 5 | 7 | 5 | 0 | 0 |
| Adjusted range and baseline | 3 | 7 | 3 | 0 | 0 |

The onset day is day 0. "none" means the method never gave that status during the fever.

## What we expected before running it

- Earth range only: amber on most days of the healthy period, because the in-flight base of 37.4 °C sits above the Earth upper limit. These are false alerts.
- Adjusted range: no false alerts in the healthy period. First amber about five days after onset, once the reading passes the adjusted upper limit.
- Adjusted range and baseline: no false alerts in the healthy period. First amber earlier than the adjusted range alone, after three readings in a row leave the personal baseline.
- All three methods: red on the same day, because the critical limit is fixed and nothing moves it.

## Limits

- This is a software test of the status rules on one simulated scenario. It is not clinical validation.
- All three methods run the same `getStatus` function the dashboard uses.
- The scenario and its expectations were committed before the evaluation was first run.
- Every scenario value is a demo parameter chosen by the team.
